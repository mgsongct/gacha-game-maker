# tools — 자기점검·정적분석

tree-sitter(`web-tree-sitter` + `tree-sitter-javascript`)로 소스를 구문 트리로 읽고, ast-grep(`@ast-grep/napi`) 패턴으로 품질 규칙을 찾아요. 빌드와 같은 순서로 `src/main/`을 한 스크립트로 이어 붙여 분석하고(이 앱은 main이 한 스크립트라 파일끼리 함수를 바로 부름), 결과의 줄 번호는 원본 파일로 돌려 줘요.

분석 대상: `src/main/`(한 스크립트) · `src/modules/**` · `src/boot/*.js` · `src/index.html` · **`src/style/*.css`**(ast-grep CSS) · **부속 파일** `www/sw.js` · `proxy/**` · `build/*.mjs` · `tools/**`(JS 파싱) · `pc/*.py`(python3가 있으면 구문 검사)

```bash
npm ci --prefix tools
node tools/check.mjs            # 요약 + tools/out/report.md · flow.mmd · report.json
node tools/check.mjs --strict   # 오류가 있거나 기준선보다 새로 생기거나 나빠진 항목이 있으면 exit 1 (CI)
node tools/check.mjs --diff HEAD          # 이번 변경으로 새로 생김·나빠짐·해결 (git 기준 트리에 같은 분석을 돌려 비교 → out/diff.md)
node tools/check.mjs --update-baseline    # 줄었을 때 기준선(tools/baseline.json) 낮추기 — 늘었으면 거부(코드를 고침)
node tools/rules.mjs --strict            # 규칙 전수검사(아래) — 오류 규칙에 건이 있거나 래칫 규칙이 늘면 exit 1 (CI)
node tools/check.mjs --rebase HEAD        # 도구를 고쳤을 때: 기준 커밋 코드를 지금 도구로 다시 재서 기준선을 세우고 지금 코드와 비교(새로 생김·나빠짐이면 exit 1)
node tools/test.mjs             # 도구 자체 검사
node tools/fix.mjs [--apply]    # 안 쓰는 함수·변수·액션 case 정리(기본은 미리 보기, 지운 뒤 생긴 것까지 되풀이)
node tools/fix.mjs --rule D1 [--apply]  # 규칙의 고치는 법 적용: 읽기 결과에 쓰는(또는 결과를 버린) 자리의 읽기 호출을 쓰기 접근으로(progRead→progSlot · gameRead→gameSlot · return gameRead('칸')만 하는 읽기 함수 → 그 칸 · 읽기 함수 주석에 적은 짝 「바꿀/고칠 때는 X」 → X) — 짝이 없으면 목록만(손으로)
node tools/fix.mjs --rule L2-read [--apply]  # L2 원인 「읽기가 progSlot」: 그 끝 함수 안의 progSlot 중 읽기만 하는 자리(결과에 쓰거나·버리거나·돌려주거나·순수하지 않은 함수에 넘기지 않고, 칸에 now가 없음 — D1 분석으로 판정)를 progRead로
node tools/map.mjs --why <함수 이름>      # 함수 하나 조회: 위치·계층(직접 효과)·부르는 곳·부르는 것·읽고 쓰는 상태 키·방향 위반·모듈별 연결 무게(자연 경계 그래프) — 조회를 grep으로 하지 않음
```

생성 기능과 **생성된 게임**의 QA·플레이 점검(브라우저로 실제 앱을 돌림)은 [play/README.md](play/README.md): `generate.mjs`(글 AI 응답을 파일로 주고받으며 게임 생성·재생) · `qa.mjs` · `shots.mjs` · `faults.mjs` · `test.mjs`.

## 데이터 생애주기 (`node tools/lifecycle.mjs [--ref <원안 git 기준>]`)
게임 데이터 키(G.meta.*·G.world.*·G.*·P().*)마다 **누가 언제 쓰는지**를 원안(포크 전, 기본 `49cec7a` — 원본 index.html을 src/로 나눈 커밋)과 지금 트리에서 뽑아 비교해요(`lib/lifecycle.mjs`, 결과 `out/lifecycle.md`).
- 단계: **생성**(newGame·buildNewGameDraft … 새 게임 초안, 만드는 중인 `ng.*` 포함) · **실행 중 AI**(`liveTick` — 게임이 구동되는 동안 시즌·장·이벤트·픽업·의상·톡을 AI가 만드는 원안의 경로) · **사용자**(`handle*Action` 처리기와 최상위 이벤트 리스너가 부르는 함수) · **불러오기**(fix·defaults·applyMeta)
- 포크가 더한 키(원안에 없던 키)가 원안의 생성·실행 경계 어디에 붙었는지: 아무 단계도 안 씀 · 사용자 조작으로만 씀 · 생성·실행 중 AI 밖
- `--why <키>`: 단계 시작점에서 그 키를 쓰는 함수까지 가장 짧은 호출 경로(예: `실행 중 AI: liveTick → liveFill → auditFixOne → AUDIT_RULES.run → spotsAuto`) — 결과를 설명하고 오탐을 가릴 때
- 함수를 담은 최상위 표(`AUDIT_RULES`의 `fix.run`·`test` 등)는 속성별 의사 함수(`AUDIT_RULES.run`)로 그래프에 들어가요(`lib/graph.mjs`). 그 속성을 멤버로 호출하는 함수만 이어지고, 표를 참조만 하는 곳은 잇지 않아요
- 한계: 동적 키 쓰기(`P()[k]=v`)는 못 따라가요(아무도 안 씀으로 나옴 — 도구 문제인지 코드 문제인지 따로 가림)

## 규칙 전수검사 (`node tools/rules.mjs [--strict] [--update-baseline] [--rebase <커밋>]` → `tools/out/rules.md`·`rules.json`)

사용자 지시: 하나씩 고치지 말고 전수검사 — 도구는 자동화만이 아니라 하나의 원칙과 규칙으로 제어하는 것. 원칙(CLAUDE.md §0-2·§0-1)을 **규칙표 한곳**(`lib/rules.mjs` — 규칙마다 원칙 · 판정 · 고치는 법 하나 · 막는 정도)에 두고, SPA에 들어가는 코드 전체(src/main · src/modules · src/boot)에 한 번에 돌림. check.mjs의 분석(lib/analyze.mjs)과 연관 맵의 data 쓰기(lib/map.mjs)를 받아 규칙마다 건을 모음.
- **계층 정의 `LAYER_DEF`**(`lib/arch.mjs` — 모든 계층 규칙이 이 하나로): 직접 효과만 봄(화면 바꿈 V · 화면 읽기 I · 상태 바꿈 S — 앱 함수 호출은 간선, 외부와의 경계인 입출력 어댑터는 S) → V∧S 섞임 · V View · S는 액션 처리기·다시 그리게 함(render·toast·openModal·closeModal)·화면 읽기가 있으면 Controller 아니면 Model · 효과 없으면 호출로(바꾸는 함수와 화면 함수를 함께 → Controller, 화면 함수만 → View). 바꾸는 함수 = S가 있거나 바꾸는 함수를 부르는(이어서) 함수. 방향: L2 View → 바꾸는 함수(render만 뺌) · L3 Model → 화면 함수
- **규칙**: L1 계층 섞임 · L2 그리다가 바꿈(원인 4가지 — 처리 호출 · 읽기가 progSlot · 없으면 만들어 씀 · 상태 바꿈, 원인마다 고치는 법 하나, 끝 함수별 건수) · L3 처리가 화면을 부름 · L4 Model이 화면 요소를 받음 · D1 읽기 결과에 쓰기 · D2 저장 표시 없는 상태 쓰기 · S1 갈래 없는 저장 키 · N1 정의 안 된 이름 · N2 TDZ · E1 순수 모듈 참조 · P1 프롬프트가 스튜디오 밖 · X1 HTML에 이스케이프 없이
- **막는 정도**: 오류(건이 있으면 실패) · 래칫(파일별 건수 — tools/baseline.json의 rules, 옮김은 합계로) · 보고. 판정(규칙)을 바꾸면 `--rebase <직전 커밋>`으로 그 커밋 코드를 새 규칙으로 재서 기준선 — 지금 코드로 올리지 않음

## 연관 맵 (`node tools/map.mjs [--check] [--split] [--why <말>] [--game <폴더>] [--force]` → `docs/map.md`·`docs/map.json`)

사용자 지시: 모듈 집합(`src/`) → 빌드 → `www/index.html`(생성기·실행기·편집기 — CLAUDE.md §0) → 생성·실행·편집 → data 게임 파일(`data/<게임id>/<종류>.json`)의 연결을 맵으로 두고, 연관 지점을 매번 다시 찾지 않고 맵을 따라감(`lib/map.mjs`).
- **data 경로**: 상태 키(G·G.meta·G.world·P() — `lib/flow.mjs`) + 생성 중인 게임(ng.* — 생성기 어휘) + 엔티티 필드(캐릭터·장·스테이지·적·세력 …의 `[].필드`). 엔티티는 컬렉션 순회·찾기 함수·컬렉션에 넣는 생성 함수·목록 변수·대입, 호출 지점에서 매개변수로 전파, 종류를 모르는 매개변수는 그 엔티티에만 있는 필드를 둘 넘게 쓰면 그 종류(구조 판정 — 이름으로 짐작하지 않음)
- **역할**: 생성기(새 게임 생성 단계에서 닿음) · 실행기(실행 중 AI·불러오기·앱을 열 때, 사용자 조작이 진행 prog.json을 씀, 또는 플레이 조작 — 진행을 쓰는 사용자 함수, 진행 칸 접근 `progSlot('cres')` 등으로 받은 객체에 쓰는 것 포함, 액션 분배기 제외 — 에서 두 단계 안의 콘텐츠 쓰기, 예: 건조 바리에이션) · 편집기(사용자 조작이 플레이 조작을 거치지 않고 콘텐츠를 씀) · 기타. 모듈 안 클릭 리스너·단위를 넘는 호출(main → 전투 모듈)도 따라감
- 경로마다 점검 규칙(`AUDIT_RULES`)·프롬프트 조각(함수 안 `pf()` + 부르는 스튜디오 함수)·읽는 모듈, 함수마다 src 파일:줄·index.html 줄, 모듈마다 index.html 줄 범위·연계 모듈(호출 수), 시험 게임에 값이 있는지
- **증분 갱신**: 입력(src 파일·www/index.html·시험 게임 data·맵 도구 자신) 해시가 그대로면 다시 만들지 않음, 바뀌었으면 다시 만들고 이전 맵과 비교해 바뀐 연결(함수 추가·삭제·옮김, data 경로의 만드는 곳)을 "최근 변화"에 남김. `--check`는 맵이 낡았으면 실패(CI)
- **index.html 기능 표면(화면 단위)**(사용자 지시 — 모듈은 원안 한 파일을 고려 없이 나눈 것이라 문제가 있다는 전제로, 분류의 기준은 지금 모듈이 아니라 산출물이 사용자에게 보여 주고 수행하는 기능, `lib/surface.mjs` — 화면 단위만으로 모듈을 판정하지 않음, 판정은 아키텍처): 아래 탭(src/index.html `.tab`) → 화면(render 경로표 · 경로 → 탭 표 · 이름은 `pageHead`) → 설정 하위 화면(`[[키, 이름…]]` 목록 + `{ 키: 내용 }` 표)의 패널(`<div class="panel"><h3>` 덩어리·`xxxPanel()`) → 창(openModal을 바로 부르는 함수, 이름은 `head('…')`) + 배경(새 게임 생성·실행 중 AI·불러오기·앱 시작). 한 단위만 여는 창은 그 단위 안, 여럿이 열면 공용 창. 함수는 호출·이름 참조·동작(data-act → 처리기 case)을 따라 **가장 가까운 기능 단위**에 붙임(다른 기능의 시작 함수에서 멈춤, 허브 함수는 건너뜀, 같은 거리면 같이 씀 — 공용·엔진)
- **아키텍처(`lib/arch.mjs` — CLAUDE.md §0-2, `docs/research/developer-role.md`)**: ① 계층(MVC) — 함수 자신이 하는 일로 View(HTML 마크업 글·DOM 바꿈)·Controller(액션 처리기 또는 render·toast·openModal·closeModal을 부름)·Model(게임 상태 씀·저장소 쓰기·네트워크·AI·그림 서비스, 또는 화면과 관계없는 계산)·**섞임**(화면을 만들며 상태·저장·서비스를 직접 씀), **방향 위반**(View가 상태·저장·서비스를 바꾸는 함수를 부름 — 그리다가 바꿈·지연 생성 / Model이 화면 함수를 부름) ② 기능 — Model·Controller 함수를 호출 + 같은 상태 키·data 경로·저장소 키(2~8개 함수만 쓰는 것)로 이어 모듈성 최대화로 묶음(순서를 바꿔 6번, 과반이 같이 묶인 것만), View 함수는 부르는 Model·Controller의 기능으로, 이름 = 가장 많이 쓰는 데이터(30개↑ 함수가 쓰는 것은 뺌), 이어진 화면 = 그 기능 함수에 닿는 화면 단위 ③ 모듈 판정(코드 냄새) — 슈퍼(관계없는 기능 둘↑ 각 max(3,20%)↑ — 발산적 변경) · 조각(중심 기능 함수가 다른 모듈에 2배↑ — 게으른 모듈, 집 = 그 기능 함수가 가장 많은 모듈 중 층·분배 아닌 곳) · 흩어짐(어느 기능도 절반 미만, 셋↑) · 고유 · 기반(허브 중심) · 분배(액션 분배기 층) · 층(프롬프트 스튜디오) ④ 저장 정책 — 코드가 쓰는 브라우저 저장소 키(함수 안·최상위 문장)마다 앱의 저장 정책 표 `STORE_POLICY`의 갈래(동기화·비밀·기기·캐시·예전 키, 게임 저장·sessionStorage는 저절로), 갈래 없는 키 = 위반, 표에만 있는 키 = 낡은 표. `docs/map.md` 3~5절, `--why <모듈>`로 판정 근거. `--strict`: 모듈마다 섞인 함수·방향 위반 수, 슈퍼·조각·흩어짐, 갈래 없는 저장 키가 기준선(`tools/baseline.json`의 `arch`)보다 늘면 실패(CI), `--update-baseline`은 줄어들 때만(새 판정 종류는 처음 잰 값)
- **섞인 함수 나누기 계획**: `--split [원안 커밋 — 기본 tools/fork-features.json의 upstreamSrc]` → `tools/out/split.md` — 섞인 함수마다 ① 생애주기 도구의 단계 그래프(생성·실행 중 AI·사용자 처리기·불러오기 시작점)에서 가장 짧은 호출 경로(그 함수를 부르는 Controller 자리)와 닿는 화면(`lib/surface.mjs`) ② 원안 트리를 같은 도구로 재서 원안부터 섞였는지·분할 뒤 섞였는지·포크가 더했는지 ③ 기능과 집 모듈(Model을 둘 곳) ④ 섞인 꼴(정산+결과 · 그리면서 상태 씀 · 창+처리 · 작업+진행 표시 · 화면 조작+상태)과 꼴에 맞는 나눔 ⑤ 요소 매개변수(`lib/arch.mjs` elementParams — 화면이 아닌 함수가 단추·칸 요소를 받아 직접 만지거나 그런 자리로 넘김, 호출 그래프 고정점) — 처리기가 `uiProg`로 만든 진행 알림을 넘기게
- **섞인 함수 나눌 자리**: `--why <함수 이름>` — View(마크업·DOM 바꿈) 줄과 Model(상태 쓰기·저장·서비스) 줄, 액션 처리기는 창 HTML·DOM을 만지는 case. 직접 신호 없이 View 함수만 엮는 함수(예: 칩 여럿을 `chipOn`으로)는 View, `classList.contains` 같은 읽기는 화면 바꿈이 아님
- **거꾸로 따라가기**: `--why chars.json › [].skills` · `--why 이격`(docs/modules.md 그 말 줄의 필드·함수·모듈) · `--why balRemasterAI` · `--game tools/play/games/<이름>`(그 게임에 값이 없는 경로와 만드는 곳) · `--why 상점`(기능 단위 이름 — 그 단위의 함수 수·얽힌 모듈·창)

## 식을 함수로 떼기 (`node tools/extract.mjs --at <src 파일:줄> --call <호출 이름> [--arg n] --name <새 함수> --doc "설명" [--to <src 파일>] [--dry]`)

섞인 함수(`map.mjs --split`)의 화면 식(예: `openModal(…)`의 창 HTML)을 View 함수로 떼어 그 함수를 Controller·Model로 남김. 식이 쓰는 이름 중 그 함수 안에서 묶인 지역 이름만 인자로(`lib/scope.mjs` freeNames — 최상위·전역 이름은 그대로라 뜻이 같음), await·this·바깥 지역 이름에 쓰기가 든 식은 옮기지 않음. 새 함수는 원래 함수 바로 앞(또는 `--to` 파일 끝). 한 파일에서 여러 번 뗄 때는 아래 줄부터(위에 함수가 들어가 줄이 밀림). 뗀 뒤 빌드·`check.mjs --strict`(정의 안 된 이름·TDZ)·브라우저 시험

## 코드 옮기기 (`node tools/move.mjs --to <src 파일> [--head 제목] 이름,… [--dry]`)

최상위 선언(function·const·let — 바로 위 설명 주석(`//` 줄·`/* */`)과 같은 줄 뒤 주석째, 파일 머리말 `/* =====`·옮김 표식은 남김)을 이름으로 찾아 다른 src 파일로 원문 그대로 옮겨요. 과잉 분할·기능 섞임·기능 분산(자연 경계)을 고쳐 한 기능을 한 모듈로 모을 때. 옮긴 뒤 불러올 때 아직 없는 이름(TDZ)이 생기면 되돌려요. 옮겨 붙인 묶음에는 `/* <원래 파일>에서 옮김 */` 표식이 붙으니 구획 설명으로 바꾸세요. 최상위 문장(리스너 등록 등)은 옮기지 않으니 원래 파일에 남은 것을 확인하세요. 프롬프트 코드는 `tools/prompts-move.mjs`(`--req` 요청 조립 식 — 지역 값·화면 입력은 인자로, `--fns --only` 조립 함수, 목록 파일 — 지시문을 스튜디오 조각으로).

## 구버전·미비 생성 게임 감지·보완 (`node tools/wiring.mjs` 표 · `node tools/play/upgrade.mjs`)

생성기·실행기가 바뀌어도 예전 빌드로 만든·빠진 데 있는 게임을 지금 앱이 알아채고 채우는지. 정적(`tools/lib/upgrade.mjs`): 포크 기능이 새로 만든 키·필드(원안 생성기가 쓰던 키는 원안 코드에서 같은 방법으로 구해 뺌)마다 불러오기 이전(`fix`가 씀) · 콘텐츠 점검 규칙(`AUDIT_RULES`의 test·fix가 읽는 키·필드, 판 since) · 실행 중 AI · 없으면 기본값 — 경로 없음이 늘면 배선 래칫 실패, 기본값으로만은 주의. 동적: 항목마다 그 데이터만 뺀 예전 게임(점검 판·생성 판 0)을 지금 빌드에 불러와 점검 알림·점검 발견·자동 보완(앱의 liveFill + 규칙 고치기, 가짜 글 AI) 뒤 채워졌나(가짜 글 AI는 형식 견본을 그럴듯한 답으로 채워 답함 — `lib/combos.mjs` `fakeAnswer`: 빈 글 채움·고르기 견본 하나씩·객체 하나짜리 목록은 가짓수만큼, 앱의 답 검사를 통과해 채우기까지 가게), 보완 뒤 다른 점검 항목이 새로 생기거나 늘었나(자동 채움 대상이 아니면 "새 문제" — 종료 코드 1, 대상이면 "이어서 채울 항목") — 정적 표는 후보, 동적이 판정(실행 중 AI 쓰기가 다른 조건에서만 일어나는 경우를 잡음).

## 포크 기능 배선 점검 (`node tools/wiring.mjs [--strict] [--update-baseline]`)
포크 기능의 데이터가 **원안의 생성 경계**(생성 = 세계관·기본 원칙 / 실행 중 AI = 시나리오·콘텐츠 / 사용자)에 맞게 만들어지는지, 생성된 게임에 실제로 들어갔는지를 tree-sitter로 맞춰 봐요(`lib/wiring.mjs`, 목록 `fork-features.json`, 결과 `out/wiring.md`). 단계 구분은 데이터 생애주기(`lib/lifecycle.mjs`)와 같아요.

| 단계 | 방법 |
|---|---|
| 기능의 범위 | `fork-features.json`의 커밋마다 그 커밋 트리 − 부모 트리의 최상위 함수. git 트리의 `src/`만 `out/ref-src/<sha>/`에 풀어 캐시 |
| 기능이 읽는 데이터 | 그 함수들이 읽는 `G.meta.*`·`G.world.*`·`G.*`·`P().*` 키 + 게임 컬렉션 콜백·찾기 함수에 묶인 변수에서 읽는 **원본에 없던 필드** |
| 누가 만드나 | 생성 단계(새 게임 초안)의 `ng.*`·`G.*` 대입·`Object.assign` 리터럴·프롬프트 스키마(`부모/키`), 실행 중 AI 단계(liveTick 경로)의 쓰기, 사용자 조작 처리기의 쓰기 |
| 기능 쪽 기본값 | `키 \|\| 기본값`·`Object.assign(기본값, 키)`·`if(!x.키) x.키 = 기본값`·`Array.isArray(x.키) ? x.키 : 기본값`(읽을 때 기본값) — 빈 값인지 쓸 만한 값인지 리터럴로 판단. 원본 샘플 기본값은 `DEFAULT_META`·`DEFAULT_WORLD`·`DEFAULT_PROG` 리터럴 |
| 생성된 게임 | `pc/data`(PC 서버 data 폴더)의 게임(샘플 main 제외) — 값·빔·기본값·없음 |

판정: **P0** 어느 단계도 만들지 않아 기능이 비어 있음 · **P1** 사용자 조작으로만 만들어짐(자동이 기본) / 생성 단계 키인데 생성 게임에 없음 / 공통·샘플 기본값으로만 시작 / 기능이 읽는 새 필드를 생성·실행 중 AI가 만들지 않음. **실행 중 AI가 만드는 키는 생성 직후 없어도 정상.** 생성기가 정할 것이 아닌 키(사용자 설정)·공통 기본값으로 충분한 키·플레이 중 생기는 필드는 `fork-features.json`의 `userKeys`·`defaultOk`·`runtimeFields`에 **사유와 함께**. 판정은 `baseline.json`의 `wiring`으로 래칫(CI `--strict`).

## 이름 규칙 (`node tools/names.mjs [--apply] [--strict] [--update-baseline]`)
분석이 헷갈리는 원인(같은 지역 이름 `b`·`e`·`x`가 배너·버튼·캐릭터, 적·이벤트·오류처럼 여러 종류에 쓰임)을 코드 품질 문제로 보고 정리하는 도구예요(`lib/names.mjs`, 규칙 `naming.json`, 결과 `out/names.md`).
- **자동 모으기**: 종류를 코드로 아는 바인딩만 셈 — 게임 컬렉션 콜백(`G.chars.map(c => …)`·`.stages`·`.enemies`·`G.lib`·`factions()`·`ELEMS` …), 찾기 함수 호출 자체(`const c = charById(…)`, `$('#x')` — `$('#x').value`처럼 호출 결과의 멤버는 아님), 이벤트 리스너 매개변수, catch 매개변수. 이름 × 종류 표
- **규칙**: `naming.json`(게임 엔티티 종류마다 고유 이름, 오류·이벤트 객체는 `e` 공유, DOM 요소 `el`). 자동 제안(가장 많이 쓴 이름)은 보고서에 참고로만
- **모호한 이름**: 규칙 이름이 아니면서 다른 종류에도 쓰이는 이름(`src/` 전체)
- **치환** `--apply`: 범위 안에 새 이름이 이미 있거나, 바깥 범위의 같은 이름을 가리게 되거나, 구조 분해 단축 속성이면 건너뜀. 단축 속성 `{c}`는 `{c: ch}`로. 바꾼 뒤 빌드·테스트
- **래칫**: 파일별 개수를 `baseline.json`의 `names`로(CI `--strict`)

## 위반 래칫 (기준선·변경 비교)
- 모든 발견(오류·경고·복잡한 함수·복잡한 익명 콜백·분배기 case·동기 순환·안 쓰는 코드·되풀이 문자열·빈 catch(파일·종류별 개수)·흩어진 상태·쓰기만 하는 키·발신 없는 처리기·안 쓰는 CSS·도구 메타 점검)을 **줄 번호 없는 키**로 바꿔 비교해요(`lib/ratchet.mjs`). 줄만 밀린 것은 같은 항목
- **새로 생김**(기준에 없던 키) · **나빠짐**(같은 항목의 복잡도·줄·중첩·횟수·개수 증가) · 해결 · 좋아짐 · **옮김**(코드를 다른 파일로 옮겨 키의 경로만 바뀐 것 — 경로가 위치일 뿐인 범주(빈 catch·이름 모호의 파일별 개수, 연관 맵의 모듈별 섞인 함수·방향 위반 수, 영역 침범·기능 분산·남의 상태 쓰기·복잡도의 함수·상태 키)만, 경로를 뺀 정체로 짝을 맞춰 그 합계가 기준보다 늘지 않았을 때. 실패가 아니고 `out/baseline-diff.md`에 따로 보고. 모듈이 정체인 과잉 분할·기능 섞임은 짝짓지 않음)
- 기준선 `tools/baseline.json`은 커밋돼 있고, CI의 `--strict`가 새로 생김·나빠짐을 막아요. 점검 항목을 새로 늘려 원래 있던 것이 처음 보이게 됐을 때만 `--update-baseline --force`(커밋 메시지에 이유)
- **도구를 고쳤을 때**(판정이 바뀌어 기준선과 안 맞음): 지금 코드로 기준선을 다시 세우지 않고, 이전 커밋 코드를 지금 도구로 재서 기준선을 세움 — `node tools/check.mjs --rebase <커밋>` · `node tools/map.mjs --rebase <커밋>`(기준 트리 `out/ref-tree/<sha>/`에 src·www/index.html을 풀어 잼). 그 뒤 지금 코드가 그보다 새로 생기거나 나빠지면 실패
- `--diff <기준>`은 기준 커밋을 `out/ref/<sha>/`에 풀어(git archive) 같은 분석을 돌려요

## 메타 점검 (도구 자체)
- 도구 코드(`tools/**`, `build/*.mjs` — node_modules·out·fixtures·games·reports 제외)도 앱과 같은 규칙으로 봐요: 파싱 오류·빈 catch·복잡한 함수·복잡한 익명 콜백·같은 본문·되풀이 문자열·안 쓰는 함수. 보고서 끝 "도구 자체" 절, 래칫 대상
- 큰 익명 콜백(`page.evaluate(async () => {…})`, `addEventListener('click', e => {…})`)은 이름이 없어 함수 그래프에 안 들어가므로 `complexAnon`이 따로 재요. 이름은 `둘러싼 함수→부른 함수 @파일`

## 규칙 늘리기
- tree-sitter 분석은 `lib/graph.mjs`(구조)·`lib/flow.mjs`(흐름), ast-grep 패턴은 `lib/quality.mjs`의 `sgRules`
- 새 규칙을 넣으면 `test.mjs`의 예시 src에 그 문제를 하나 심고 잡히는지 확인

## 알려진 한계
- 멤버 호출(`obj.method()`)·문자열로 부르는 함수(`window[name]()`)는 그래프에 안 들어가요(안 쓰는 함수 판단은 이름 문자열 검색이라 안전한 쪽)
- 상태 흐름은 `G`·`P()`와 같은 함수 안 별칭만 따라가요. 다른 함수로 넘긴 객체(`c`, `ch`)의 변경은 저장 표시 검사에서 빠져요
- 화면에 안 보이는 설정은 휴리스틱(화면 함수 이름 규칙)이라 내부 표시값이 섞일 수 있어요
- HTML 주입은 글 모양 속성 이름(`.name`·`.desc`…)과 `T()`·`sub()`만 봐요. 지역 변수에 담았다 넣는 글(`const n=c.name; …${n}`)이나 다른 함수가 만든 HTML 조각은 못 따라가요
- DOM id는 정적 문자열만 봐요(`$('#'+id)`처럼 이어 붙인 선택자는 건너뜀). 안 쓰는 CSS 클래스는 이름 검색이라, 문자열을 쪼개 만드는 클래스는 쓰는 것으로 못 볼 수 있어요(목록만, 오류·경고 아님)
- 리스너 누수는 "다른 함수가 부르는 함수"를 여러 번 도는 것으로 봐요. 실제로 한 번만 부르면 경고가 지나칠 수 있어요
