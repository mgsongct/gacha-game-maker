# 사용자 지시 대장

사용자가 내린 지시·방법·원칙·가이드·「해야 한다」고 한 것을 **원문 그대로** 모으고, 각 지시가 어느 원칙(CLAUDE.md 절)으로 올라가 있고 무엇으로 지켜지는지(도구 점검·시험·절차) 적는 곳입니다(사용자 지시 2026-11-04: 「지시와 방법과 원칙, 가이드, 해야한다고 한것들 관리하고 있나?」).

- 새 지시는 받는 즉시 여기에 원문으로 적고, CLAUDE.md의 해당 절에 원칙으로 올립니다. 내 해석·가정은 적지 않습니다(CLAUDE.md 머리).
- 작업을 시작할 때와 단계를 바꿀 때 이 대장과 CLAUDE.md를 확인합니다.
- 「지키는 방법」이 도구가 아닌 것(절차만)은 도구로 옮길 대상입니다 — 표의 「도구화」 칸.
- 어긴 일은 「어긴 기록」에 적고 원인을 고칩니다(도구에 없는 측정을 grep으로 대신한 것 같은).

## CLAUDE.md에 이미 올라 있는 지시(예전 대화)

CLAUDE.md에서 「(사용자 지시)」「(사용자)」「(사용자 지적)」「(사용자 결정)」으로 표시된 항목이 예전 대화의 지시입니다. 원문은 그 대화에 있고, 여기서는 절만 가리킵니다.

| 절 | 지시 | 지키는 방법 |
|---|---|---|
| §0 | 게임(생성물)이 아니라 생성기·규칙 엔진·프롬프트를 고침 · index.html = 생성기·실행기·편집기 · 연관 맵을 따라감 · JSON data 저장 | `node tools/map.mjs`(`--why`) |
| §0-1 | 모듈 영역 침범·파편화 없게 · 조각 모듈을 고유 모듈로 통합 · 기능 분류는 index.html 기능 추상화 기준 · 전수검사·규칙표 · 프롬프트는 스튜디오 한곳 | `tools/modules.mjs --strict` · `tools/rules.mjs --strict` · `tools/check.mjs --strict` |
| §0-2 | 계층 분리(MVC) · 기능 하나 = 모듈 하나 · 저장 정책(브라우저 = 캐시, 원본 = data/) | 규칙 L1–L4·D1·D2·S1 (`tools/rules.mjs`) |
| §2 | 측정·검증은 도구로 · 임시 도구를 두지 않음 · 위반을 늘리지 않음 · 오탐이면 원인을 가려 도구나 소스를 고침 | `check.mjs --strict`·`rules.mjs --strict`(CI) — 「도구로 잰다」 자체는 아직 절차 |
| §3 | 한국어 · 모호하면 묻기 · 원안 기준 이해 · 내 가정을 지시처럼 적지 않음 · 문제 목록·연구·해결 | 절차 |
