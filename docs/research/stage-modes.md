# 스테이지 양식: 전투 · 이야기 · 회담 · 콘테스트

## 1. 현황
- 스테이지는 전투(적 전멸) 또는 이야기(전투 없음) 두 가지뿐. 협상·재판·오디션·축제처럼 이야기가 전투가 아닌 장면에서도 억지로 전투를 넣거나 대본만 흘려 보냄
- 캐릭터의 개성(성격·매력)이 게임 판정에 쓰이는 곳이 없음

## 2. 장르 조사(공통 구조만, 특정 게임의 이름·대사·연출은 쓰지 않음)
| 양식 | 참고한 구조 | 일러스트만으로 되는가 |
|---|---|---|
| 회담·법정형(역전재판식) | 상대의 증언을 한 줄씩 넘겨 보며 **추궁**(더 캐묻기)과 **증거 제시**(모순을 밝힘), 틀리면 페널티 게이지 감소, 0이면 실패 | 증언 문장 + 상대 상반신 + 증거 카드 |
| 설득·협상형 | 상대의 관심사·약점에 맞는 동료나 논거를 고름 | 스탠딩 + 선택지 |
| 콘테스트형(포켓몬 콘테스트식) | 매력 분류(멋·귀여움·아름다움·지성·강인함), 심사위원 취향, 라운드별 어필, 연속 어필·순서에 따른 분위기(콤보), 경쟁자와 점수 비교 | 캐릭터 카드 + 점수판 |

## 3. 이 앱의 결정 (`src/main/0488-stage-modes.js`)

### 회담 `s.mode='debate'`
- 상대·목표·증거(3~5개)·라운드(주장 요약 + 상대의 말 3~5줄)
- 줄마다: **추궁**(press 대답을 들음) · **증거 제시**(그 줄의 `weak`와 같은 증거면 돌파) · **동료 설득**(`persuade.who` — 이름·역할·소속이 맞는 동료가 편성에 있으면 돌파)
- 라운드마다 돌파 1번. 틀린 증거·설득은 신뢰도 −1(기본 5), 0이면 실패(다시 도전). 성공 대사·실패 대사
- 별: 신뢰도를 하나도 안 잃으면 ★3, 절반 이상 남기면 ★2

### 콘테스트 `s.mode='contest'`
- 심사위원 1~3명(좋아하는 매력), 라운드 2~5, 경쟁자(power 0.6~1.6)
- **매력 `charmOf(c)`**: 개성 시트(핵심 성격·반전 매력·취미·좋아함·상징)와 프로필의 낱말로 5가지 매력을 정하고, 역할(공격=멋·강인함, 방어=강인함, 지원=지성)·희귀도·호감도·레벨로 키움
- 라운드마다 출전자 1명 + 어필 종류: 점수 = 매력 × (그 라운드 심사위원 취향이면 1.6) × (1 + 0.12 × 분위기)
- 분위기: 취향 적중 +1, 다른 출전자로 이어 가면 +1, 같은 출전자를 연달아 쓰면 0으로(최대 4)
- 1위면 통과. 경쟁자 점수는 우리 출전자 매력을 기준으로 power배

### 공통
- 진입 화면에서 함께 갈 동료(회담 최대 4명·설득용)·출전자(콘테스트 최대 3명)를 고름. 첫 이야기(pre) → 양식 → 클리어 뒤 이야기(post), 첫 클리어 보상·별·첫 등장 캐릭터 인연·장 끝 합류는 다른 스테이지와 같음
- 작전 지도에 양식 아이콘(⚖ 회담, ✦ 콘테스트)

### AI 생성 연계
- 프롬프트 조각 `STAGE_MODES`: 대부분 전투, 이야기에 맞을 때 한 장에 0~2개를 회담·콘테스트로. 회담은 협상·재판·심문·설득, 콘테스트는 축제·오디션·무대·대회·사교 파티. 증거는 앞선 이야기에서 얻은 물건·증언·기록
- `stageSchema`(장·이벤트)와 새 게임 1장 스키마에 `mode`·`debate`·`contest`. `modeClean`이 검증(증거 id가 줄의 weak와 맞는지, 돌파 가능한 줄이 있는지, 매력 이름)하고 틀리면 전투로
- 설정 → 게임 → 전투 체계에서 양식별로 끄면 프롬프트와 검증에서 빠짐

## 4. 확장 아이디어
- 증거를 앞선 스테이지·시나리오 설계의 복선에서 얻어 이어 쓰기(증거 가방)
- 회담의 "흔들기"(같은 주장을 여러 번 추궁하면 새 줄이 생김), 제시 대상으로 인물 프로필
- 콘테스트 의상(스킨)·감정 연출(0462) 연동, 관객 반응 이벤트
- 조사(장소에서 단서 찾기)·잠입·추격·요리 같은 양식 추가 — `modeClean`과 화면 함수 한 쌍으로 늘릴 수 있음
