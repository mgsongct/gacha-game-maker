# 세력 설계 · 적·몬스터 도감 · 등장/영입(캐스팅) 정합성

## 1. 현황 조사 (변경 전)

| 항목 | 상태 |
|---|---|
| 세력 | `G.world.factions = [{name, desc}]` — 이름과 한 줄 설명뿐. 종류(플레이어블·적대·중립·괴물), 목적·지도자·거점·이념, 세력끼리의 관계, **플레이어와의 관계 변화**(처음엔 적 → 나중에 동료 등)를 담을 곳이 없음 |
| 적·몬스터 | 자료실 적은 이름·외형 프롬프트뿐. **그것이 무엇인지(정체·습성·약점)** 정한 곳이 없고 얕음을 판정하지 않음 |
| 몬스터의 커뮤 대상화 | 장 생성의 `newCharacters`·`newNpcs`에 AI가 몬스터를 넣으면 그대로 캐릭터·NPC가 됨 → 뽑기·톡·일정·인연 대상이 됨(검사 없음) |
| 샘플 데이터 | 캐릭터 소속 「회색구 연합」이 세력 목록에 없음(목록에는 「회색구 시민회」) |
| 첫 등장과 뽑기 | 스토리 신규 캐릭터는 `c.debut`을 깨기 전 상시 뽑기에서 빠지지만 **픽업 배너는 예외**라 만나기 전에 뽑힘. 처음부터 있는 캐릭터는 뽑아서 편성해도 스토리 AI가 그 사실을 모름 → **함께 싸운 캐릭터가 나중에 첫 만남처럼 등장** |
| 세력 적대와 영입 | 소속 세력이 적대 중이어도 뽑기에 그대로 나옴 |

## 2. 장르 조사(공통 패턴)
- **세력 설계 항목**: 목적·지도자·거점·이념·자원·비밀, 세력 사이 관계표. 진영형 가챠 게임은 세력마다 메인 스토리에서의 역할(초반 적 → 후반 협력)이 정해져 있음
- **적 도감**: 몬스터의 기원·습성·약점을 도감에 공개해 전투(약점)와 세계관을 잇는 방식
- **스토리 해금 캐릭터**: 메인 스토리 특정 장을 깨야 상시 모집에 들어가거나, 해당 장 클리어 전에는 픽업이 열리지 않는 방식. 반대로 "이미 사무소에 소속된 동료"로 설정해 뽑은 뒤 개인 스토리(인연)로 사연을 푸는 방식
- 적이었던 인물이 동료가 되는 경우, 적으로 나오는 구간 동안에는 모집에 나오지 않게 하는 것이 흔함

## 3. 이 앱의 결정 (`src/main/0445-factions.js`)

### 세력
| 항목 | 내용 |
|---|---|
| kind | playable(플레이어블 소속) · hostile(적대 세력) · neutral(중립) · monster(괴물·마물 무리). 없으면 소속 캐릭터·적 이름으로 추정 |
| 설정 | 개요·목적·지도자·거점·이념·숨겨진 사실(작가용), 몬스터 무리는 정체·습성·약점 |
| rel | 다른 세력과의 관계(동맹·적대·긴장·이용…) |
| stance | 플레이어와의 관계를 장마다: `[{ch:1,s:'hostile'},{ch:4,s:'ally',why}]`. 비우면 종류대로(플레이어블=우호, 적대·괴물=적대, 중립=중립) |

- AI 컨텍스트(`factionCtx`): 세력마다 종류·지금 관계·**앞으로 바뀔 관계(아직 드러내지 않음)**·설정·소속, 적 도감(몬스터는 말하는 동료·NPC·메신저 상대가 아님)
- 장 생성 JSON에 `stance`(이 장에서 관계가 바뀌는 세력) → 그 장부터 기록(`stanceApply`)
- 캐릭터 소속인데 목록에 없는 세력은 자동으로 목록에 넣고(플레이어블) 깊이 점검에 걸림

### 적·몬스터 도감
- 자료실 적(캐릭터가 아닌 것)마다 무리·정체·습성·약점. 샘플 게임 적 8종은 기본값을 채움
- **몬스터 차단** `isMonsterLike`: 적 목록의 몬스터 이름, 외형이 "no humans", 역할이 몬스터·괴물·마물…, 소속이 괴물 무리 → `newCharacters`·`newNpcs`에서 캐릭터·NPC로 만들지 않고 적으로 등록
- 예전 데이터: 점검 `c_monster` → "몬스터로 전환"(`c.monster`: 뽑기·건조·톡·일정·AI 동료 목록에서 빠지고 적으로 등록)

### 깊이 점검 `factionReview`(0~100)
세력 2개 미만, 적대 세력·몬스터 무리 없음, 개요가 짧음, 목적·지도자·거점·이념 빠짐, 몬스터의 정체·습성·약점 빠짐, 세력 관계 없음, 정체 없는 적, 몬스터로 보이는 캐릭터·NPC. AI로 깊이 채우기(이름·이미 있는 사실은 유지, 추가 지시 가능). 점검 `w_faction`(70점 미만)

### 등장·영입(캐스팅)
| 규칙 | 기본 |
|---|---|
| 첫 등장 전 잠금 | `c.debut` 스테이지를 깨기 전에는 상시·**픽업**·건조 모두 안 나옴(설정에서 픽업 예외로 바꿀 수 있음) |
| 적대 세력 잠금 | 소속 세력이 지금 적대면 아직 보유하지 않은 캐릭터는 뽑기·건조에서 잠금 |
| 만나지 않은 보유 캐릭터 | 처음부터 뽑을 수 있는 캐릭터를 뽑았지만 스토리에서 아직 안 만났으면, AI에 "이미 계약으로 합류해 함께 작전 중인 동료(첫 만남처럼 쓰지 않는다)"로 알림 |
| 아직 등장 전 | AI에 "정해진 첫 등장 장면에서만 처음 만난다"로 알림 |
| 첫 등장 정하기 | 세력·몬스터·등장 관리 → 등장·영입에서 캐릭터마다 첫 등장 스테이지(또는 처음부터) |
| 점검 `c_debut` | 메인 스토리 2장 이후에 처음 말하는데 처음부터 뽑을 수 있는(미보유) 캐릭터 → 그 스테이지를 첫 등장으로 |

생성 규칙 버전 8입니다. 캐릭터 개인 스토리·톡·일정·인연은 원래 보유해야 열려요(이번에 몬스터 캐릭터를 추가로 막음).

## 4. 확장 아이디어
- 세력 평판(호감) 수치와 세력 상점·세력 의뢰
- 적대 → 동맹 전환 때 그 세력 캐릭터 일괄 해금 알림·기념 픽업
- 몬스터 도감 해금(처음 쓰러뜨리면 정체 공개, 여러 번 잡으면 약점 공개)
- 캐릭터 단위 관계 변화(배신·이탈) 타임라인
