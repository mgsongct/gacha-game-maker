# 콘텐츠 점검·업그레이드 (생성 기능 향상·구버전 생성물 대응)

## 1. 문제

AI로 만든 콘텐츠(캐릭터·대본·그림)는 만들 당시의 생성 규칙을 따릅니다. 앱이 좋아지면(새 필드, 바뀐 프롬프트 규칙, 새 전투 규칙, 바리에이션 같은 새 기능) **예전에 만든 것은 그대로 남습니다.** 또 생성이 중간에 실패하거나 AI가 일부 항목을 빠뜨린 경우도 있습니다.

이 앱에는 이미 두 장치가 있었습니다.
- `fix()`: 불러올 때마다 도는 **구조 마이그레이션**(빠진 필드 기본값, 버전 플래그 1회 변환). 데이터 형식만 고치고 내용은 만들지 않습니다.
- 캐릭터별 **다시 만들기**(`openRegen`)와 **일괄 그림**(`runPrep`): 사람이 하나씩 골라야 합니다.

빠져 있던 것은 **"무엇이 낡았거나 빠졌는지 찾아 주고, 한꺼번에 고치는"** 층입니다.

## 2. 설계 (`src/main/0535-content-audit.js`)

### 2.1 규칙 레지스트리 `AUDIT_RULES`

```js
{ id, scope: 'char'|'stage'|'lib', kind: 'missing'|'upgrade', since: <생성 규칙 버전>, label,
  test(o) → true면 문제, fix: { mode: 'auto'|'ai'|'ai-stage'|'weapon'|'skills'|'image'|'open', ... } }
```

| 종류 | 뜻 |
|---|---|
| `missing` | 빠졌거나 잘못됨(대사 없음, 그림 없음, 금지 태그 등) |
| `upgrade` | 구버전 생성물. 지금 기능으로 바꾸면 좋아짐(전투 규칙, 상징 컬러·아이템, 구버전 생성기) |

| 고치는 방법 | 동작 |
|---|---|
| `auto` | 규칙으로 바로 변환(AI 없음). 예: 나이 태그 제거, 상징 컬러·아이템 추정 |
| `ai` | **빠진 항목만** AI로 채움. 이미 있는 내용은 살리라고 지시 |
| `ai-stage` | 빈 스테이지 대본을 대본 형식(`SCRIPT_FMT`)으로 작성 |
| `weapon`, `skills` | 기존 기능 재사용: `fixWeaponPrompts`, `v2Ensure` + `v2ReadyChars`(밸런스 검사) |
| `image` | 기존 `runPrep`으로 빠진 그림만 |
| `open` | 기존 편집 화면(`openRegen`)을 열어 사람이 고름. 구버전 표시를 지움 |

### 2.2 생성 버전 `genVer`

- 새로 만드는 캐릭터는 모두 `cleanChar0`를 거치므로, 거기서 `genVer = auditGenVer()`를 찍습니다.
- `genVer`가 없거나 낮으면 **구버전 생성물**입니다. 기본 제공 샘플 캐릭터(`DEFAULT_CHARS`)는 손으로 쓴 것이라 제외합니다.
- `auditVer()` = 규칙들의 최대 `since`. `G.meta.auditSeen`보다 크면 "**생성 기능 향상**" 배지가 붙고, 켤 때 한 번 알려 줍니다.

### 2.3 지정 변환

사용자가 대상 캐릭터·항목(프로필·첫 대사·평소 대사·터치·호감도·레벨업·돌파 대사·외모 태그)·지시문을 정하면 AI가 그 항목만 고칩니다. 예: "대사를 모두 반말로", "프로필에 출신지 추가", "외모 태그를 겨울 분위기로". 외모 태그는 나이·금지 태그를 다시 걸러서 저장합니다.

### 2.4 안전

- **되돌리기**: 일괄 작업마다 대상의 직전 상태를 남겨 두어, 마지막 작업 1번을 되돌릴 수 있습니다(`auditUndo`).
- 이격을 고치면 상속 수정치(`over`)가 자동으로 다시 계산됩니다([variants.md §3](variants.md#3-상속형-관리-원본--수정치)).
- AI 작업은 하나씩 순서대로 진행하고, 진행 표시와 멈추기가 있습니다. 실패한 항목은 건너뜁니다.

## 3. 생성 기능이 좋아졌을 때 개발자가 할 일

1. 생성 프롬프트나 스키마를 바꿨으면 `auditGenVer()`를 1 올립니다.
2. 예전 생성물을 감지할 규칙을 `AUDIT_RULES`에 추가하고 `since`를 새 버전으로 둡니다.
   - 형식만 바꾸면 되는 것 → `auto`
   - 내용을 새로 써야 하는 것 → `ai`(필드 목록) 또는 새 `mode`
3. 데이터 구조가 바뀌어 불러오기부터 깨지는 경우는 여기가 아니라 `fix()`에 버전 플래그로 넣습니다(구조 마이그레이션은 자동, 내용 업그레이드는 사용자가 확인 후).
4. `build/test.mjs` 12번에 감지·고치기 확인을 추가합니다.

예: v2에서 바리에이션이 생기면서 "상징 컬러·아이템"이 필요해짐 → `c_symbol`(upgrade, since 2, auto). v3에서 바리에이션·상속이 들어오며 구버전 캐릭터 표시 → `c_old`(upgrade, since 3, open).

|---|---|---|---|---|
| `c_profile` | 캐릭터 | 빠짐 | 프로필 40자 미만 | AI |
| `c_lines` | 캐릭터 | 빠짐 | 평소 대사 3개 미만 | AI |
| `c_touch` | 캐릭터 | 빠짐 | 터치 반응 없음 | AI |
| `c_aff` | 캐릭터 | 빠짐 | 호감도 대사 없음 | AI |
| `c_intro` | 캐릭터 | 빠짐 | 첫 대사 없음 | AI |
| `c_look` | 캐릭터 | 빠짐 | 외모 태그 없음 | AI |
| `c_age` | 캐릭터 | 빠짐 | 외모 태그에 나이 태그(예전 생성물) | 자동 |
| `c_minor` | 캐릭터 | 빠짐 | 금지 태그 | 자동 |
| `c_weapon` | 캐릭터 | 빠짐 | 무기 그림 프롬프트 없음·잘못됨 | AI(기존 기능) |
| `c_skills` | 캐릭터 | 구버전 | 전투 v2·현재 밸런스 규칙과 다름 | 다시 맞추기 |
| `c_symbol` | 캐릭터 | 구버전 | 상징 컬러·아이템 없음 | 자동 추정 |
| `c_old` | 캐릭터 | 구버전 | `genVer` < 현재 | 다시 만들기 열기 + 표시 갱신 |
| `c_img` | 캐릭터 | 빠짐 | 스탠딩·상반신·일러스트·무기 그림 없음 | 그림 |
| `s_script` | 스테이지 | 빠짐 | 전투 전 대본 없음 | AI |
| `l_img` | 자료 | 빠짐 | 배경·소품·CG·적 그림 없음 | 그림 |
