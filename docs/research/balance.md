# 밸런스 관리: 파워 인플레 · AI 생성 편차 · 보수 · 구캐릭터 AS

## 1. 문제 (조사 결과)

| 원인 | 코드에서 확인한 것 |
|---|---|
| **세대 인플레** | 전투 v2의 "출시 세대" 1~5가 스킬 예산을 키움: 패시브·액티브·필살기 예산 × 1 / 1.2 / 1.45 / 1.75 / 2.1 (`GENERATIONS`). 새 캐릭터는 그때 세대로 만들어지고 그 세대로 남음 → 세대를 올릴수록 옛 캐릭터가 구식 |
| **AI 능력치 편차** | AI가 쓴 능력치는 범위만 자름(체력 600~2000, 공격 60~200, 방어 20~120, 속도 70~130 — `cleanChar0`). 방어형만 기본형 표로 만들고 나머지는 AI 값 그대로 → 같은 희귀도·역할끼리도 전투력이 크게 다름 |
| 기존 장치 | 스킬은 밸런스 검사(기준 편성과 모의 전투, 목표 승률)로 맞춤. 능력치·세대는 검사 대상이 아니었음 |

전투력은 캐릭터 화면과 같은 식 `체력/5 + 공격×3 + 방어×2 + 속도`(성장 전 기본값)로 봅니다. 기준값은 희귀도·전투 기본형의 기본 능력치(게임 규칙의 기본형 능력치·희귀도 배율)로 계산합니다.

## 2. 장르 조사

- 라이브 서비스 가챠는 새 캐릭터가 메타를 장악하고 옛 캐릭터가 몇 달 안에 밀리는 일이 흔함
- 대응: **수평적 확장**(숫자보다 새 빌드·선택지), 시즌으로 격차를 줄이기, 옛 캐릭터가 전략·지원·카운터로 남게 하는 설계
- 옛 캐릭터를 **깎는 방식은 수집 투자를 무너뜨림** → 낮추기보다 맞춰 올리기
- 단, 수평 확장은 "복잡도 인플레"를 부를 수 있음

## 3. 이 앱의 결정 (`src/main/0187-balance.js`, 엔진 `genBoost`)

설정 → 게임 → **밸런스 관리**. 저장: `G.meta.balance`.

| 기능 | 선택지 | 효과 |
|---|---|---|
| **세대 정책** | 수동(기존: 시즌 운영 설정) · **고정**(모든 새 캐릭터 같은 세대 → 인플레 없음) · **자동 상승**(새 캐릭터 N명마다 1세대, 최대 세대까지) | 새 캐릭터의 출시 세대 |
| **구캐릭터 AS** | 끔 · **전투 보정**(현재 세대보다 낮으면 세대 차이당 체력·공격·방어 +x%, 최대 y% — 저장값은 그대로) · **리마스터**(허용 차이보다 뒤처진 캐릭터의 세대를 올리고, 글 AI가 있으면 저장된 스킬 설계 의도·이름을 지키며 새 세대 예산으로 스킬을 다시 설계 — 스킬 검사는 너무 강한 것만 약화해 세대만 올려서는 예전 스킬이 그대로라서. 그 뒤 스킬 밸런스 재검사) | 오래된 캐릭터가 구식이 되지 않게 |
| **능력치 균질화** | 허용 편차 ±% (기본 15) | 기준값에서 벗어난 캐릭터 표시 |
| **보수** | 범위 안으로(가장 가까운 끝까지) · 기준값으로 | 속도는 두고 체력·공격·방어를 **같은 비율로** 맞춰서 성향(체력형·공격형)은 유지. 스킬 밸런스는 다시 검사 |
| **생성 시 자동 보정** | 켬(기본) | AI가 만든 새 캐릭터가 범위를 벗어나면 바로 범위 안으로 |
| **점검 결과** | 희귀도별 기준 대비 범위·세대 범위, 캐릭터별 편차·세대·스킬 검사 필요 | 선택해서 보수·세대 맞추기·스킬 재검사, 되돌리기 |

- 콘텐츠 점검에도 `c_statband`(능력치 범위 밖 → 자동 보수), `c_genlag`(세대 뒤처짐 → 세대 맞추기)가 잡힙니다.
- 전투 보정은 전투·밸런스 검사(워커 포함)에 `v2Options().genBoost`로 같이 들어갑니다.

## 4. 수치 예

| 설정 | 결과 |
|---|---|
| 고정 1세대 | 계속 같은 예산 → 인플레 없음. 새 캐릭터는 설계(스킬 조합·포지션)로 차별화 |
| 자동, 기준 1, 5명마다, 최대 3 | 15명째부터 3세대에서 멈춤(1→2→3) |
| AS 전투 보정 세대당 +8%, 최대 30% | 1세대 캐릭터가 4세대 환경에서 +24% |
| AS 리마스터, 허용 차이 1 | 현재 4세대면 1·2세대 캐릭터를 3세대로 올리고 스킬 재검사 |
| 허용 편차 15%, 보수 "범위 안으로" | 기준 838인 SR 공격형이 966(+15.3%)이면 체력·공격·방어를 같은 비율로 줄여 +15% 안으로 |

## 5. 확장 아이디어

- 스킬 예산 자체의 편차 점검(같은 세대·희귀도끼리 모의 전투 승률 분포)
- 시즌마다 구캐릭터 일부를 골라 "리마스터 시즌" 이벤트로 연출
- 수평 확장 지원: 새 캐릭터 생성 시 이미 많은 포지션·속성 조합을 피하도록 AI에 알려 주기
