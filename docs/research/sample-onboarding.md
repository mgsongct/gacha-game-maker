# 첫 실행·샘플 게임·기다리는 동안 (제안 단계)

키 없이 처음 연 사람이 보는 것(샘플 게임 「낙성계약」)과, 키를 넣고 첫 게임이 나오기까지의 경험을 점검하고 개선안을 정리합니다. 종합 점검은 [maker-review.md](maker-review.md).

## 2. 조사

| 주제 | 요점 | 이 앱에 |
|---|---|---|
| 튜토리얼의 효과 | 4만 5천 명 이상·3개 게임·8가지 설계 비교에서 튜토리얼은 **가장 복잡한 게임에서만** 플레이 시간을 최대 29% 늘렸고, 단순한 게임에서는 효과가 없었음. 플레이어는 글보다 직접 해 보며 배움[1] | 메이커(설정·생성·점검)는 복잡하니 상황별 도움말이 값어치 있고, 만들어진 게임 쪽 안내는 짧게 — "첫 뽑기 → 편성 → 출격" 한 번이면 충분 |
| 곧바로 성공 경험 | 열자마자 재미있는 행동을 하게 하고 튜토리얼 안에서 성공을 맛보게 하라는 권고. 첫 몇 분(FTUE)은 1일차 잔존율로 잼[2][3] | 샘플의 첫 화면에 인물이 없고, 가장 큰 버튼이 막혀 있음(S1·S4) |
| 잔존율 기준값 | GameAnalytics 2026 중위 D1 약 22%·D7 4%·D30 0.7%, 상위 25%는 D1 30%를 조금 넘음[4]. "재미까지 걸리는 시간"을 분 단위로 정한 공인 기준은 찾지 못함 **[미확인]** | 개인 앱이라 잔존율은 참고만. 대신 "키 없는 사람이 첫 캐릭터를 보기까지 클릭 수"를 앱 내 지표로 |
| 응답 시간 한계 | 0.1초·1초·10초가 사용자 주의의 경계[5]. AI 응답이 10초를 넘으면 퍼센트 진행률을 보여 주라는 권고[6] | 새 게임은 순차 complex 호출 4회 — 단계 수 기준 퍼센트 + 지금 단계 이름 + 만들어진 결과를 바로 보여 주기 |
| 체감 대기 | 진행 막대 줄무늬를 거꾸로·점점 느리게 움직이면 체감 시간 11% 감소[7]. 스트리밍이 체감 속도를 높인다는 1차 연구는 찾지 못함 **[미확인]** | 진행 표시를 단계마다 끊지 말고 이어지게 |
| 중간 결과를 사람이 고치기 | 인간-AI 상호작용 가이드라인 18개(처음·사용 중·틀렸을 때·시간이 지난 뒤)[8], Google PAIR 가이드북의 "피드백과 통제"[9] | 생성 초안이 이미 단계별로 저장되므로(`DR.r`) 단계 결과 확인·수정 화면을 붙이기 쉬움 |
| 그림 생성 진행률 | ComfyUI는 `/ws`의 `progress` 메시지로 실제 진행률을 줌[10] | 캐스팅·일괄 그림에서 실제 진행률 표시 |

## 3. 제안

| # | 제안 | 해결 | 위치 | 규모 |
|---|---|---|---|---|
| 3-1 | **그림 없는 상태의 기본 표현**: 그림이 없을 때 등급·속성 색·역할 실루엣·이름 머리글자·상징(`symbol`)으로 만든 **SVG 초상**을 그려 대원 카드·스토리 서 있는 자리·뽑기 결과에 사용(샘플뿐 아니라 그림 생성 전의 모든 게임에 해당). 파일 크기 거의 0 | S1 | `imgSrc`(`0080-storage-integration.js:57`) 대체 경로, 카드·스토리 렌더 | M |
| 3-2 | **샘플 갱신을 콘텐츠 점검으로**: 샘플에 `auditFix`의 자동 변환·지정 변환을 적용한 결과를 `0050-default-content.js`로 굳히고(스킬 규칙·상징·포지션·사거리·연출·전장 규칙), 메모리얼·인연 톡·대사 4개·시나리오 설계(로그라인·막)를 손으로 채움. 빌드 테스트에 "샘플 점검 결과 0건(그림 제외)" 고정 | S2·S3 | `0050-default-content.js`, `build/test.mjs` | M |
| 3-3 | **샘플 그림 소량 동봉 여부 결정**: 대원 8명 스탠딩만 WebP로 넣으면 1장당 수십 KB 단위로 파일이 커짐 — 3-1의 SVG 초상과 비교해 결정 | S1 | `www/` 자산 또는 `0050` | S(결정) |
| 3-4 | **첫 행동 순서 고정**: 대원 0명이면 로비 큰 버튼을 "첫 계약"으로 바꾸고, 첫 뽑기 → 편성 → 1-1 출격 순으로 한 번만 안내 | S4 | `lobbyHTML`(`0180-ui-scroll.js:71`) | S |
| 3-5 | **빠른 시작**: 0번 화면에 "글 AI 키만 넣고 바로 만들기" — 그림·목소리 단계는 게임을 만든 뒤 설정에서. 그림 AI가 없으면 3-1 초상으로 진행 | S5 | `renderSetup`·`swdone` | S |
| 3-6 | **생성 대기 화면**: 단계 이름만이 아니라 단계 기준 퍼센트와 지금까지 만든 것(게임 제목·세력·대원 이름)을 바로 보여 주고, 끝나기 전에 고칠 수 있게(초안이 이미 단계별로 저장됨 `DR.r`) | S5 | `buildNewGameDraft`의 `stat()`·초안 화면(`0260`) | M |
| 3-7 | **키 없이도 초안 열기**: 마지막 화면에서 초안 버튼을 항상 보이고, 키가 없으면 "AI 없이 직접 만들기" 탭으로 열기 | S6 | `renderSetup`(`0210:63~64`) | S |

## 4. 수치

- 샘플 점검 104건 중 그림 37건은 키 없이는 못 고침 → 3-2 목표는 **나머지 67건 → 0건**.
- 3-1 초상 1장 = SVG 한 줄(수백 바이트). 대원 8명 스탠딩 WebP 동봉은 수백 KB 증가 예상(정확한 값은 시험 변환으로 확인).
