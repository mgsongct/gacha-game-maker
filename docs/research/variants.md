# 바리에이션 (이격·영의 등 "다른 모습")

## 1. 조사: 장르의 공통 패턴

| 이름(예) | 의미 | 보통 얻는 법 |
|---|---|---|
| 이격(異格) | 같은 인물의 다른 버전 유닛. 성능·역할이 다를 수 있음 | 기간 한정 가챠 |
| 스킨·의상 | 외형만 바뀜, 성능 같음 | 유료 상점·이벤트 |
| 시즌 의상(수영복·축제·정장 등) | 계절 이벤트마다 같은 틀(수영복, 공연의상 …)로 여러 캐릭터가 한꺼번에 나옴 | 이벤트 가챠·이벤트 보상 |

공통점: **틀(테마)은 공통이고 대상 캐릭터만 바뀝니다.** 수영복 이벤트라면 "수영복"이라는 틀 하나에 그 시즌 대상 캐릭터 여럿이 붙고, 각 캐릭터의 상징색·소품·성격이 의상 디자인에 들어갑니다.

이 앱에는 이미 두 경로가 있습니다.
- **이격**(`c.alt` = 원래 캐릭터 id): 시즌 운영·픽업 만들기에서 `aiAltChar(원래 캐릭터, 테마)`로 생성. 별도 유닛이고, 가챠 픽업 배너로 풀림
- **스킨**(`c.skins`): 외형만 바뀌는 의상

바리에이션은 **이격과 같은 데이터(`c.alt`)를 쓰고, 공통 템플릿(`c.cvar` = 템플릿 id)과 건조 경로를 더한 것**입니다.

## 2. 이 앱의 결정

| 항목 | 결정 |
|---|---|
| 설정 단위 | 캐릭터마다가 아니라 **공통 템플릿** `G.meta.variants[]` 하나에 적용 조건을 겁니다. 조건에 맞는 보유 캐릭터는 모두 자동으로 대상이 됩니다 |
| 기본 템플릿 | 수영복 · 교복 · 갑옷 · 공연의상1/2/3 (설정에서 추가·삭제·수정) |
| 여는 법 | 건조/영입이 켜져 있을 때만. 템플릿마다 레시피(`recipe.min[4]`)가 있고, 레시피가 맞고 대상이 있으면 `chance`% 로 바리에이션이 나옴. 4번째 자원(기본 "부품")을 400 이상 넣어야 하도록 기본 레시피를 잡아서 **res4 = 바리에이션 열쇠**가 되게 했음 |
| 대상 조건 | 소속, 역할, 속성, 희귀도, 능력치(hp/atk/def/spd 비교), 최소 레벨, 최소 돌파, 최소 호감도, 업적(클리어한 스테이지 id). 비우면 조건 없음 |
| 대상 기준 | 원래 캐릭터를 **가챠 등으로 이미 보유**해야 함(요청: "가챠로 획득한 캐릭터의 다른 모습"). 이미 그 바리에이션을 보유한 캐릭터는 대상에서 빠짐 |
| 가챠와의 관계 | 건조/영입이 켜져 있으면 바리에이션(`cvar`)은 가챠 풀에서 빠짐(픽업으로 직접 넣은 경우 예외) |
| 등급 | 템플릿마다 "원래 캐릭터와 같게" 또는 R/SR/SSR |
| 생성 | 처음 나올 때 만듦. **글 AI가 있으면** `aiAltChar`에 디자인 지시(`designBrief`)를 넘겨 이름·프로필·대사·naiPrompt를 씀. **없으면** 규칙으로 만듦(원래 캐릭터 복제 + `variantPrompt`). 그림 AI가 설정돼 있으면 이어서 그림을 그림(`runPrep`) |

## 3. 상속형 관리 (원본 + 수정치)

이격·바리에이션은 원본을 복사해 따로 두지 않고, **원본과 다른 항목만 수정치(`c.over`)로 저장**합니다(git 패치처럼). 원본을 고치면 수정치가 없는 항목은 이격에도 같이 반영됩니다. 구현: `src/main/0065-inherit.js`.

| 구분 | 항목 |
|---|---|
| 상속(원본을 따름, 바꾸면 수정치로) | 소속 `faction`, 속성 `elem`, 포지션 `role`, 희귀도, 스킬 `skills`(+밸런스 결과), 프로필·대사·터치·호감도/레벨/돌파 대사·기밀 파일, 나이, 목소리, 그림체 |
| 능력치(가중치) | `hp/atk/def/spd`는 원본 대비 배율 `over.statMul`로 저장. 원본 공격 170, 이격 204 → `atk ×1.2`. 원본이 220이 되면 이격은 264 |
| 이격 자기 것(상속 안 함) | id, 이름, 모든 그림(스탠딩·일러스트·상반신·로비·CG·표정·스킨), 외모 프롬프트 `naiPrompt`, 에피소드, 전용 무기 |

- 이격을 기존 캐릭터 편집 화면에서 고치면 저장할 때(`mark('c:'+id)`) 원본과 비교해 수정치가 자동으로 다시 계산됩니다.
- 원본을 고치면 그 원본의 이격들에 바로 반영됩니다(`inheritOnMark`).
- 캐릭터 화면에 "원본 「X」을(를) 물려받아요"와 바꾼 항목 칩이 나오고, 칩을 누르면 그 항목만 원본 값으로 되돌립니다("모두 원본 따르기"도 있음).
- 저장 데이터(IndexedDB, PC `data/<게임>/chars.json`)에는 이격이 **수정치와 자기 것만** 들어 있습니다. 불러올 때 원본 + 수정치로 다시 채웁니다(`fix()` → `inheritAll`).
- 예전 이격(전체 복사본)은 처음 불러올 때 지금 값 그대로 수정치를 만들어서 보이는 값이 바뀌지 않습니다.
- 원본을 지우면 그 이격은 다음 저장부터 전체 값으로 저장됩니다(물려받을 곳이 없으니까).

## 4. 디자인 프롬프트 조합 (`GGMConstruct.variantPrompt`)

```
원래 캐릭터 naiPrompt
  − 옷·소품 태그(dress, coat, bodysuit, armor, holding … 정규식 CLOTHES)
  − 구도 태그(full body, standing …)
+ 템플릿 의상 태그 (예: swimsuit, beach, summer, sunlight)
+ 상징 컬러: c.symColor 또는 naiPrompt의 "<색> hair/eyes" 태그 → "<색> color scheme outfit, <색> accents"
+ 상징 아이템: c.symItem 또는 전용 무기 prompt의 앞 태그 2개 → "<아이템> motif accessory"
+ full body, standing, simple background, white background
```

예) 세라 `1girl, solo, tall, long crimson hair, sharp amber eyes, black tactical bodysuit, long dark coat, holding sniper rifle, cool expression` + 수영복 →
`1girl, solo, tall, long crimson hair, sharp amber eyes, cool expression, swimsuit, beach, summer, sunlight, crimson color scheme outfit, crimson accents, long sniper rifle with red scope motif accessory, full body, standing, simple background, white background`

AI 경로는 같은 정보를 문장으로 넘깁니다(`designBrief`): 기본형 이름·태그, 상징 컬러·아이템, 성격을 의상에 녹이라는 지시, 템플릿의 "디자인 추가 지시". AI 결과에 템플릿 첫 태그가 없으면 규칙 프롬프트로 바꿉니다.

`c.symColor`, `c.symItem`은 선택 필드입니다. 없으면 위 규칙으로 추정합니다(영어가 아닌 값은 이미지 태그에 넣지 않음).

## 5. 안전

- 등장인물은 모두 성인(앱 규칙, `age ≥ 20`), 미성년 태그 필터(`MINOR_TAGS`)는 그대로 적용됩니다.
- "교복" 기본형은 `blazer, formal school-style uniform cosplay, adult`로 성인 코스튬임을 태그로 명시합니다. 원치 않으면 설정에서 끄거나 지우세요.

## 6. 확장 아이디어

- 바리에이션 전용 스킬·성능 차이: 지금은 AI 경로에서 AI가 정하고, 규칙 경로에서는 원래 캐릭터 스킬을 그대로 씀. 템플릿에 `statMul`, `role` 덮어쓰기 추가 가능
- 템플릿별 전용 스토리(에피소드): 처음 얻을 때 `aiPickupStory`류로 짧은 에피소드 생성
- 시즌 연동: 시즌 로테이션(`SEASONS`)의 이벤트 시즌에 특정 템플릿 확률 업
- 조건 종류 추가: `condMatch`에 항목을 더하고 설정 행(`conVariantRow`)에 입력칸 추가

## 7. 출처

장르 관례(이격·시즌 의상)는 일반적인 서브컬처 가챠 게임 관행을 정리한 것이고, 이 앱의 기존 구현(`aiAltChar`, 스킨 상점)을 기준으로 설계했습니다. 수치·조건은 이 앱용으로 새로 정했습니다.
