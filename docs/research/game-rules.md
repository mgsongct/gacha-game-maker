# 게임 규칙: 속성 상성 · 역할(포지션) · 능력치 · 진영

## 1. 문제 (조사 결과)

게임을 만들면 진영·포지션(역할)·속성이 정해지지만, 규칙이 코드 안에 고정돼 있어 **보이지도 않고 고칠 수도 없었습니다.**

| 항목 | 있던 곳 | 상태 |
|---|---|---|
| 속성 상성 | `applyMeta()`: `meta.elems` 순서대로 0→1→2→0 순환(`BEATS`) | 순서로만 결정. 화면에 안 보임 |
| 상성 배율 | 전투 엔진 `damage()`: 유리 ×1.5, 불리 ×0.75 하드코딩 | 바꿀 수 없음, 공개 안 됨 |
| 역할 기본 능력치 | `CHARACTER_BASE_STATS`: 공격 1000/120/48, 방어 2400/85/128, 지원 950/100/46 | 새 캐릭터 생성에 쓰임, 고정 |
| 역할 속도 | `roleSpeed()`: 공격 108 · 방어 80 · 지원 86 (+이름 해시 −3~+3) | 고정 |
| 희귀도 배율 | `generateBaseStats()`: 체력 1/1.04/1.12, 공격 1/1.15/1.4, 방어 1/1.1/1.12 | 고정 |
| 진영 | 세계관 `world.factions`(이름·설명), 도감 | 전투 효과 없음(스킬 대상 "같은 소속의 아군"만) |
| 역할·속성 이름 | 게임 정의 편집에서 이름·색만 | 설명 없음 |
| 캐릭터별 값 | 캐릭터 편집(작가 모드)에서 속성·역할·능력치 | 개별 편집만 가능 |

## 2. 장르 조사

| 요소 | 흔한 방식 |
|---|---|
| 속성 상성 | 3속성 순환(가위바위보)이 가장 흔함. 배율은 게임마다 크게 다름: 소폭(+10% 전후, 불리해도 감소 없이 빗나감 확률만) ~ 대폭(×1.5/×0.75) |
| 진영 상성 | 진영 사이 유리 관계로 피해 +25% 같은 방식 |
| 진영 시너지 | 같은 진영을 여러 명(예: 3+2, 4명) 편성하면 공격·체력 보너스. 모든 진영으로 치는 특수 진영도 있음 |
| 역할 | 역할마다 기본 능력치 성향(탱커=체력·방어, 딜러=공격·속도, 지원=회복·버프) |

## 3. 이 앱의 결정 (`src/main/0185-game-rules.js`, 전투 엔진 `030-core.js`)

설정 → 게임 → **게임 규칙 (상성·능력치)** 에서 보고 고칩니다. 저장은 `G.meta.rules`이고, **비운 칸은 기존 기본값**이라 아무것도 안 바꾸면 전투 결과가 예전과 똑같습니다.

| 규칙 | 편집 | 반영 |
|---|---|---|
| 속성 이름·색·**설명** | 속성마다 | 캐릭터 화면, 도감 |
| **이기는 속성** | 속성마다 고름(`beatIdx`). 기본 순환 0→1→2→0 | `BEATS` → 전투 |
| **유리·불리 배율** | `elemAdv`(1.5) · `elemDis`(0.75) | 전투 엔진 `damage()` |
| 역할 이름·**설명** | 역할마다 | 캐릭터 화면, 도감 |
| **역할 기본 능력치·속도** | 체력·공격·방어·속도(R 기준) | `GGMCombat.applyRules()` → 새 캐릭터 생성. "기존 캐릭터 능력치 다시 계산" 버튼으로 이미 있는 캐릭터에도(이격은 상속 배율대로 따라감) |
| **희귀도 배율** | 체력·공격·방어 × R/SR/SSR | 같은 곳 |
| **진영 시너지** | 같은 진영 n명 이상이면 공격·방어 +% (`synergy`, 기본 끔) | 전투 시작 시 `synergy()` |
| **관계 배율** | 진영·역할·속성 A가 B를 공격하면 ×배율 (`rel[]`) | `damage()`에서 속성 상성과 곱함 |

- 캐릭터 화면(장비·스킬 탭 맨 위)에 "속성 홍 — 녹에 강함(×1.5) · 청에 약함(×0.75) / 역할 / 진영(시너지)"이 나옵니다.
- **도감에 규칙 기록**: `[규칙] 속성 상성`, `[규칙] 역할`, `[규칙] 진영 시너지`, `[규칙] 관계` 항목을 도감(로어북)에 만들거나 고칩니다.
- **AI로 설명 채우기**: 세계관에 맞는 속성·역할 한 줄 설명을 생성합니다.
- **새 게임 생성**: AI가 속성 설명(`d`)과 역할 설명(`roleDesc`)도 함께 만듭니다.
- **구버전 게임**: 콘텐츠 점검에 `g_rules`(설명 없음 → AI로 채우기), `g_codex`(도감에 규칙 없음 → 자동 기록)가 잡힙니다.
- 전투·밸런스 검사(Web Worker 포함)는 `v2Options()`로 같은 규칙을 받습니다. 역할 기본 능력치는 새 캐릭터 생성(메인 화면)에서만 쓰여서 워커와 어긋날 일이 없습니다.

## 3-1. 속성 추가·제거·상성표·반응 (2차 확장)

| 기능 | 내용 |
|---|---|
| 속성 개수 | **2~8개**. 규칙 화면에서 추가·삭제·이름·색·설명. 삭제한 속성의 캐릭터·NPC·스테이지 적은 첫 속성으로, 이름을 바꾸면 모든 곳에서 함께 바뀜(`rulesRename`) |
| 이김 | 속성마다 이기는 속성 하나(또는 없음). 이름으로 저장(`rules.beats`) |
| **상성표** | 공격 속성(행) × 맞는 속성(열) N×N 배율. 비운 칸 = "이김"과 유리·불리 배율로 계산. 전투 엔진은 이 표(`elemMat`)를 그대로 씀 |
| **반응** | A 속성에 맞은 대상에 흔적(기본 4초)이 남고, 그 안에 B 속성으로 맞으면 반응: **증폭**(피해 ×값) · **폭발**(공격력×값 추가 피해) · **기절**(값 초) · **취약**(받는 피해 +값%, dur초). "순서 무관"이면 B→A도 발동. 반응이 나면 흔적이 사라짐 |

## 3-2. 포지션 (명일방주 직군·칸코레 함종처럼)

전투 엔진에는 기본형 3개(공격·방어·지원)가 있고, 스킬 생성·AI 행동·기본 능력치가 이 기본형을 씁니다. **포지션은 기본형 하나를 고르고 그 위에 기능을 얹은 것**이라, 포지션을 몇 개로 늘려도 스킬 생성·밸런스 검사가 깨지지 않습니다.

| 포지션 기능(`t`) | 효과 |
|---|---|
| 체력·공격·방어·속도 % | 전투 시작 시 능력치 보정 |
| 주는 피해 % / 받는 피해 % | 모든 피해에 곱함 |
| 회복량 % | 주는 회복량 |
| 치명타 %p | 치명타 확률 |
| 시작 SP | 필살기 게이지를 미리 채움(선봉형) |
| 위협도 % | 적이 고르는 대상 가중치. 높으면 더 맞고(방벽), 낮으면 덜 맞음(사수) |

- 프리셋: **기본 3**, **직군형 8**(선봉·근접·방벽·사수·술사·의무·보조·특수), **함종형 6**(구축·경순·중순·전함·항모·잠수), **AI로 세계관에 맞게 설계**
- 새 게임을 만들 때 AI가 포지션 4~8개, 속성 3~5개(이김 관계), 반응 0~4개를 같이 만듦
- 캐릭터: `c.pos` + `c.role`(=포지션 기본형). 캐릭터 편집에서 포지션 선택, AI가 새 캐릭터를 만들 때 포지션 이름으로 고름, "포지션 자동 배정"은 기본형이 같은 포지션 중에서 고르게
- 관계 배율에 **포지션**(A 포지션 → B 포지션) 추가
- 이격은 포지션도 상속, 콘텐츠 점검 `c_pos`(포지션 없음 → 자동 배정)

## 4. 수치 예

| 설정 | 결과 |
|---|---|
| 기본 | 홍→녹→청→홍, 유리 ×1.5, 불리 ×0.75 |
| 유리 1.1, 불리 1.0 | 상성이 약한 게임(조합 자유도↑) |
| 진영 시너지 n=2, 공격 +10% | 같은 진영 2명 이상 편성한 아군 공격 ×1.1 |
| 관계: 진영 새벽등대 → 헬릭스 ×1.25 | 이야기 속 숙적 관계를 전투에 반영 |
| 방어 역할 체력 2400 → 3000 | 새 방어형 캐릭터부터 체력↑(다시 계산 버튼으로 기존에도) |

## 5. 확장 아이디어

- 시너지 단계(2명/3명/4명마다 다른 보너스), 모든 진영으로 치는 특수 진영
- 편성 화면에 시너지·상성 미리보기, 적 속성에 맞춘 추천 편성
- 역할별 성장 곡선(레벨업 능력치 증가량)
