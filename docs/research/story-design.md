# 시나리오 사전 설계 (큰 틀 → 장마다 빌드)

## 1. 현황 조사 (변경 전)

| 항목 | 상태 |
|---|---|
| 메인 장 생성 `aiChapterGen0`(`0250`) | 직전 장면 6,000자 + 기억(`memo`)·관계(`rel`) + "메인 플롯을 한 걸음 진전시키고, 복선을 하나 회수하거나 새로 깐다"는 **즉흥 지시** |
| 플롯 입력 | `w.plot`(자유 글), `G.meta.bible`, `storyCfg().plot` — 모두 자유 글. 막 구성·반전·복선 위치가 없음 |
| 반전 | 장마다 "마지막 스테이지는 반전"만 있음. 무엇을 언제 밝힐지 정해 두지 않아 복선 없는 반전, 너무 이른 폭로, 회수되지 않는 복선이 생김 |
| 분기 | 대본 `선택:`은 그 장면 안에서만 갈라짐(`S.pick`). **장을 넘어 남는 선택 기록이 없음** |

## 2. 장르 조사

| 방식 | 요점 |
|---|---|
| 3막·막 목표 | 막마다 목표(무엇이 바뀌어야 하는가)를 정하고 장을 배치 |
| 복선과 회수(Chekhov's gun) | 반전 전에 2~3번, 눈치챌 듯 말 듯 심는다. 공개 장은 복선 뒤 |
| 분기와 수렴(branch & bottleneck) | 선택은 과정·관계를 바꾸고, 큰 줄기는 정해진 결말로 모인다. 가챠 게임 메인 스토리에 흔한 형태(엔딩 하나, 선택은 대사·관계·일부 장면) |
| 캐릭터 아크 | 시작 → 변화 → 끝. 장마다 조금씩 진행 |

## 3. 이 앱의 결정 (`src/main/0465-story-plan.js`)

- `G.world.plan`: 로그라인·주제·목표 결말·막(이름, ~몇 장, 목표)·반전(진실, 공개 장, 관련 인물, 복선[장, 힌트])·분기(id, 장, 질문, 보기[보기, 이후에 바뀌는 것])·아크·메모
- **장마다 필요한 것만** `planCtx(n)`: 지금 막과 목표, 이번 장에 심을 복선, 이번 장에 밝힐 반전, **아직 밝히지 말 진실**(작가 전용), 이미 고른 분기 결과, 이번 장의 분기(대본 형식), 아크. 미래 복선은 넘기지 않음
- 분기 기록: 대본에 `[분기: id]` 다음 줄 `선택: A | B` → 고른 번호가 `P().flags[id]`에 남고, 다음 장 프롬프트에 "플레이어가 고른 분기"로 들어감
- 점검 `planCheck`: 로그라인·막 없음, 복선 없는 반전, 복선이 모두 공개 장 뒤, 공개 장이 지났는데 '공개됨' 미확인, 분기 장 대본에 `[분기: id]` 없음, 보기 2개 미만, 설계한 막을 넘어섬
- AI: 처음부터 설계 / 다듬기 / 다음 막 잇기(이미 쓴 장과 어긋나지 않게), 추가 지시
- 화면: 설정 → 게임 → 시나리오 설계

## 4. 확장 아이디어

- 분기별 다른 결말(멀티 엔딩)과 플래그 조건 스테이지
- 반전 공개 여부를 대본에서 자동 판정(AI 검사)
- 이벤트 스토리에도 같은 설계 적용

## 5. 출처
