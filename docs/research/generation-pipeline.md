이 프로젝트로 게임을 **실제로 생성**하면서(`tools/play`), 생성 기능이 어떻게 돌아가고 어디서 품질이 새는지 점검한 결과와 개선안입니다. 생성된 게임 자체의 품질은 [generated-games.md](generated-games.md), 버그·불일치는 [game-qa.md](game-qa.md), 플레이 경험은 [play-review.md](play-review.md), 종합은 [maker-review.md](maker-review.md).

## 1. 방법

- `tools/play/generate.mjs`가 앱의 실제 생성 함수(`buildNewGameDraft`·`v2GenerateSkills`·`aiChapterGen`)를 브라우저에서 돌리고, 글 AI 요청(Anthropic 형식)만 가로채 **응답 파일**로 답합니다. 응답이 없으면 앱이 보낸 프롬프트(지침·교훈·"JSON만 출력"까지 붙은 최종본)를 `prompts/`에 내놓고 멈춥니다.
- 글 AI 역할은 Claude 에이전트가 맡았습니다. 앱 소스를 보지 않고 **프롬프트만 보고** 답했고, 읽으면서 헷갈리거나 모순된 지시를 따로 보고했습니다(§3의 "글 AI 보고"). 모든 프롬프트·응답·실행 기록이 게임 폴더에 있어 그대로 다시 볼 수 있고, 응답이 모인 게임은 키 없이 **재생**됩니다(재생으로 같은 게임이 다시 만들어지는 것을 확인함).
- 실패 주입은 `tools/play/faults.mjs`(결과: `tools/play/reports/faults.md`).
- 한계: 응답 시간·실제 모델별 실패율은 재지 못했습니다(응답이 즉시 옴). 글 AI가 한 모델 계열이라, 작은 모델에서 형식 오류가 얼마나 나는지는 같은 프롬프트로 따로 받아 봐야 합니다.

## 4. 견고성 — 실패 주입 (`tools/play/reports/faults.md`)

기준 응답(`tools/play/fixtures/mini`)에서 한 가지씩 바꿔 새 게임을 만든 결과:

| 시나리오 | 게임 | 남은 문제 |
|---|---|---|
| 정상 | 만들어짐 | 스킬 설계 응답이 없으면 대원 **4/4가 임시 스킬**로 저장(백그라운드 설계 전에 저장) |
| 세계관 응답이 계속 JSON이 아님 | 안 만들어짐 | 같은 오류 알림 3번 |
| 세계관에 플롯·설정·세력 없음 | **만들어짐** | 플롯 "1부의 축: 헬릭스는 분화구 아래…"(원본 샘플) + 샘플 세력 섞임 (`Object.assign(clone(DEFAULT_WORLD),a.world)` `0250-story-factory.js:222`) |
| 대원 4명 요청에 3명(중복·없는 역할·등급 9·80자 이름·모르는 세력·빈 프로필) | **만들어짐** | 이름 중복 그대로, 모르는 세력은 플레이어블로 새로 추가(`:230`) |
| 1장 빈 응답 / 오프닝 시간 초과 | 안 만들어짐 | 그 사이 스킬 설계 호출이 계속 나감(12회) |
| 대원 단계 서버 오류 | 안 만들어짐 | 같은 오류 알림 3번 |

실제 생성에서 본 것:

- **대본 실패 시 장면 구성안이 대본으로**: 2장 스테이지 대본 요청이 끝나지 않았을 때도 2장이 열렸고, 스테이지마다 작가용 장면 구성(beats) 7~8줄이 그대로 전 대본이 됨("…마테오의 첫 등장. (CG: 구름 위의 곡예비행)" 같은 설계 메모·앞으로의 단서 포함), 후 대본은 비어 있음.
- **기억 정리가 계획을 기록**: 같은 상황에서 기억 정리 요청의 입력이 실제 대본이 아니라 장면 구성안에 "[대본]" 표시만 붙인 것이었음 → 일어나지 않은 사건이 "이야기 기억"으로 남을 수 있음.
- 새 게임은 `auditSeen`을 찍지 않아, 막 만든 게임에 "생성 기능이 좋아졌어요… N개를 업그레이드할 수 있어요" 알림이 뜸.

## 5. 결과 검증·후처리

- 단계 통과 기준(`ngStep`의 `ok`)은 "필요한 키가 있는가"뿐 — 인원·이름 중복·등급 분포·세력 이름·대본 분량을 보지 않음.
- 1장은 이후 장이 거치는 장치(스테이지별 집필·마무리·도감 기록·**조연 NPC 등록**·나중 등장 처리·모의 전투 밸런스)를 거치지 않음 → 아이돌 1장 대본의 이름 있는 조연 7명(심사위원·PD·라이벌)이 NPC로 등록되지 않아 초상·표정이 연결되지 않음([game-qa.md](game-qa.md)).
- 시나리오 설계(로그라인·막·반전)는 자동으로 만들지 않음 — 두 게임 모두 "로그라인이 없어요·막 구성이 없어요".

## 6. 비용·캐싱

- 스킬 작성 규칙(10.4K자)·출력 스키마·대본 형식 같은 **정적 덩어리가 동적 내용 뒤**에 붙고, 캐싱(`cache_control` 등)은 쓰지 않음. 2장 스테이지 대본 요청 4개는 앞부분이 같아(그래서 초기 하네스가 한 요청으로 착각할 정도) 캐싱 효과가 가장 큰 자리.
- 추정(글자 비례): 스테이지 대본 4회에서 공통 앞부분 S≈15K·고유 D≈4.5K이면 `4×19.5K=78K` → `1.25·15 + 3×0.1·15 + 4×4.5 = 41.3K`(약 47% 감소). Anthropic 캐시는 쓰기 1.25배(5분)·읽기 약 0.1배, 최신 모델 최소 512토큰(빠른 작업 기본 모델인 Haiku 4.5는 4,096토큰)[9].
- 사용량(`usage`) 기록·예상 비용·취소·화면 꺼짐 방지 없음.

| 첫 실행 | 6화면 마법사(시작 → 글 AI → 그림 AI → 그림체 → 목소리·배경음 → 게임 고르기) | 키가 있는 사람도 설정 4화면을 지나야 만들기. 키가 없으면 마지막 화면의 초안 버튼이 숨겨져(`0210-setup.js:64`) "AI 없이 직접 만들기"에 못 감 |
| 생성 대기 | 상태 한 줄("1/4 …")과 "만드는 중… 화면을 끄지 마세요" | 진행률·지금까지 만든 것·취소 없음. 순차 4회라 몇 분 걸림 |
| 실패 | 같은 알림 반복, 초안이 남아 "다시 누르면 이어서" | 어느 단계가 왜 실패했는지 한 번에 안 보임 |
| 완료 후 | 저장 즉시 새로고침 → 캐스팅 | 생성 결과(세계관·대원)를 확인·수정할 틈이 없음 |

## 8. 조사

| 주제 | 요점 | 이 앱에 |
|---|---|---|
| 계획 → 집필 | Re3: 바로 쓴 것보다 "플롯 일관" +14%p[1]. DOC: 계층 개요로 통제, Re3 대비 플롯 일관성 +22.5%p[2] | 이후 장은 이미 구성→집필. **1장도 같은 경로로**, 세계관 직후 시나리오 설계 |
| 구조화 출력 | Anthropic `output_config.format`(수치·길이 제약은 미지원, 거부·길이 초과 땐 어긋날 수 있음)[3], OpenAI Structured Outputs[4], Gemini `responseJsonSchema`[5] | 형식은 스키마로, 개수·중복·분량 같은 **의미 검사는 앱이** |
| 검증 → 수리 | 스키마로 못 하는 제약은 로컬 검증[3]. Self-Refine 평균 약 +20%p, 반복할수록 이득 감소[6] | 빠진 부분만 다시 요청, 수리 1~2회 |
| 지시 표류 | 대화 8턴 안에 시스템 지시에서 벗어남[7] | 바이블을 매 요청 **같은 앞부분**으로 — 캐싱과 같은 방향 |
| 캐싱 | Anthropic: 앞부분 바이트 일치, 중단점 4개, 쓰기 1.25배·읽기 약 0.1배, 최소 512~4,096토큰(모델별)[9]. OpenAI: 1,024토큰 이상 자동[10] **[원문 미확인]**. Gemini 2.5 이상 암시적 캐시[11] | 정적 블록을 앞으로 |
| 응답 시간·진행 표시 | 0.1·1·10초 경계[12], 10초 넘으면 퍼센트 진행률[13], 진행 막대 체감 11% 단축[14] | 단계 기준 퍼센트 + 만들어진 결과를 바로 보여 주기 |
| 중간 결과 통제 | 인간-AI 상호작용 가이드라인(처음·사용 중·틀렸을 때)[15] | 단계 결과 확인·"이 단계만 다시"(초안이 이미 단계별 저장) |
